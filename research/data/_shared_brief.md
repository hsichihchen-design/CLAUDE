# 研究小組共通簡報（給所有研究員）

## 專案背景
創作者想做一款遊戲，源自這個感悟：一位朋友原本打籃球，因某個偶然契機被找去打排球，後來排球成了他生活的一部分。
人生中很多事在發生當下只覺得普通、甚至不怎麼樣，但很久以後才發現它在不知不覺中影響了一輩子——人際關係、價值觀、習慣、興趣。
核心感受不是遺憾、懷舊、勵志或命運論，而是一種「驚奇」：原來我們之所以成為現在的自己，來自無數個當時不知道有多重要的瞬間；影響不一定正面或負面；當下無法知道真正意義。
同時要警惕：事後建構、後見之明、敘事偏誤——遊戲不應宣稱每件事都有預定意義。

遊戲要同時追求：A 真正好玩（不在乎主題也好玩）、B 自然傳播、C 商業成功（不只是好評藝術品）、D 深層餘韻（玩家自己發現，不靠旁白說教）。
不預設類型：可以是策略、經營、模擬、Roguelike、沙盒、多人、解謎或未探索的混合類型。

## 核心矛盾
玩家若事先知道哪些小事件會產生重大影響→失去不可預測性；若完全看不懂因果→覺得隨機、無聊、不公平。

## 證據規則（嚴格遵守）
1. **必須實際使用 WebSearch / WebFetch 上網查證**，不可只憑記憶。優先一手來源（論文、開發者訪談、GDC 演講、官方公告）。
2. 每項重要發現給證據編號（依你被指派的前綴）、來源標題、作者/發行者、年份、URL。
3. 證據類型標記：【一手-學術】【一手-官方】【第三方估計】【二手報導】【玩家行為】【玩家自述】【推論】【假設】。
4. 心理學研究標註：實驗（因果）／縱貫相關／橫斷相關／質性／理論推演；並標註再現性爭議。
5. 銷售數字：官方 vs 第三方估計分開；查不到寫「未知」；願望清單/觀看數不等於銷量。
6. **絕不虛構**研究、數字、評論、URL。若某 URL 無法確認，標「未直接驗證」。
7. 主動尋找反例與反駁，標示倖存者偏誤、確認偏誤、事後偏誤。
8. 研究事實、分析推論、創意假設清楚分開。

## 輸出格式
- 全部使用**繁體中文**（專有名詞、論文標題、遊戲名可保留原文）。
- Markdown 文件寫到 /home/user/CLAUDE/research/ 下指定檔名。
- 證據 CSV 寫到 /home/user/CLAUDE/research/data/ 下指定檔名，UTF-8，用標準 CSV 引號規則（含逗號的欄位要加雙引號）。共通欄位：
  `id,domain,claim_zh,source_title,author_or_publisher,year,url,evidence_type,study_design,strength,limitations_zh,game_implication_zh`
  strength 用：強／中／弱／爭議
- 不要 git commit（研究總監會統一提交）。
- 完成後回報：檔案路徑、證據編號範圍、5–10 條最關鍵發現（每條附編號）、以及你最不確定的地方。回報控制在 500 字內。
