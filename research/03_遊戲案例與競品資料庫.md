## 3. 跨案例核心發現（彙整自 03a、03b）

| # | 發現 | 依據 | 等級 |
|---|---|---|---|
| C-1 | **最強的「後來才知道」來自「記錄」與「發現」在時間上分離**：系統在事件發生當下不標記它很重要，玩家日後在另一個情境中自己把點連起來 | 03a 跨案例觀察 1；A04、A05 | 【推論】 |
| C-2 | **可追溯，但不可預先計算**：牌組構築類的因果可以預先算出來，帶來的是策略滿足，而不是驚奇 | A10、A12 | 【推論】 |
| C-3 | **手寫型延遲理解強烈但只有一次；系統型較弱但可以重複** | 03b §4 | 【推論】 |
| C-4 | **劇透脆弱度與「每位玩家的結果是否不同」高度相關**：系統型和選擇型作品看了實況，反而可能想自己買 | 03b §5；B02、B06、B07 | 【推論】（無因果證據） |
| C-5 | **哲學深刻不是賣不好的原因；「玩法弱＋團隊大」才是** | B07、B08 vs B17、B18 | 【推論】，有倖存者偏誤 |
| C-6 | **「好評 ≠ 營收」有正式財報與工作室自述佐證** | B17、B18 | 【一手-官方】 |
| C-7 | **把狀態呈現為描述，而不是數字**，是避免人生模擬變成數值管理的共同手法 | A04、A05、A03；反例 A06、A07 | 【推論】 |
| C-8 | **刻意放入「最終什麼也沒導致的小事」**：沒有任何案例系統性地這樣設計，可能是差異化空間 | 03a 觀察 3 | 【假設】 |
| C-9 | **以聯想取代因果（Immortality）**，可以避開「每件事都有預定意義」的陷阱 | B20 | 【推論】 |
| C-10 | **指標陷阱**：玩家數、下載數、擁有者數、第三方估計經常被混用；同一款遊戲各家估計可差 3–10 倍 | A01、A02、A06、B15 | 【一手-官方】＋【第三方估計】 |

## 4. 「商業成功但哲學較淺」vs「哲學深刻但商業有限」

詳見 03b §6。摘要如下：

```
            玩法強度高
                │
   Papers, Please│ Undertale        Stardew  Balatro
   Outer Wilds   │ RimWorld、DF      ACNH
   ─────────────┼─────────────────────────── 哲學／主題整合度
   Season        │                   BitLife  Reigns
   KRZ           │                   Detroit（直白、強情緒）
   Immortality   │
                │
            玩法強度低
```

**最重要的觀察**【推論】：左上角（主題深＋玩法強）的成功作品幾乎都是 **1–5 人的小團隊**。低成本讓「中等銷量」就足以構成成功。這為本專案設定了一個現實的規模目標，見文件 06、08。
